## Additional encodings

`extension-codecs` separately captures six original multibase calls (z/u/f, encode and decode) and ten original multihash calls (all four CID-defined codes plus 0x13, encode and decode). Input bytes are public bounded fixtures; decoder inputs are independent literals, never only a subject round trip. The original module ZIP, canonical h1, three cache source files, compiler and separately identified Inspector probe are checked. Missing calls, unexpected errors, bad attribution, altered source and partial evidence are ERROR, not a declaration of unsupported functionality. Base and hash capture errors remain independent after the common source premise; an error in one group does not discard the other's completed evidence.

For bytes `00 01 fe ff`, normative CID integer-base controls are `z1ftS` and `uAf7_`. Do not substitute RFC 4648 `uAAH-_w`. The selected external additional base16 fixture is `f0001feff`. Four CID multihash controls use codes 0x12/0x20/0x16/0x15 and lengths 32/48/32/48. The selected additional 0x13 fixture uses a minimally encoded code, length 0x40 and 64 ascending opaque digest octets. No cryptographic hash is computed or security property inferred.

The fixed original component explicitly refuses both operations for f and 0x13. Each refusal becomes NOT_SUPPORTED only for that selected optional encoding. It is not a mandatory conformance failure, a declaration about all additional encodings, or adapter rejection evidence. A future successful implementation must satisfy independent expected bytes; the judge does not force successful support into NOT_SUPPORTED.

Supplemental public fixture definitions are recorded with official repository commit, path, blob, whole-file SHA-256 and selected rows in [the reference record](sage-extension-references.json):

- [multibase registry](https://github.com/multiformats/multibase/blob/72573756adb8514d1741b692fe14ebea7f1c01da/multibase.csv) defines lowercase f/base16. Its u/RFC4648 description does not override CID's normative integer-base control.
- [multicodec registry](https://github.com/multiformats/multicodec/blob/8d9e9b3b3d376ee86179fc6c866f6e56f74fa167/table.csv) assigns sha2-512 code 0x13.
- [RFC 6234 section 8.1](https://www.rfc-editor.org/rfc/rfc6234.html#section-8.1) defines SHA512HashSize as 64 octets. This fixes fixture length, not a claim of hashing support.

These supplemental definitions do not replace the frozen CID publication or alter its extracted statements. The artifact checker binds the complete reviewed reference record by a literal SHA-256.

## Explicit application callback

`extension-application-handler` makes four actual original dereferencer calls with a literal public example driver and fragment-free path: handled callback, unhandled callback, absent configuration, and no-path document control. It records nested resolution and original consumption, actual callback URL/options/model/entries/metadata, callback return and final original result separately. Both the literal resource oracle and final/callback equality are checked. The absent control omits configuration; it never registers or invokes a nil function.

The observed PASS is the original dispatcher's explicit application extension point under resource.48. The callback supplies the application-specific resource; it is not SAGE method path support, an authoritative Source, network retrieval, arbitrary application correctness or full dereferencing conformance. False/absent/no-path outcomes are diagnostic controls, not invented mandatory obligations for a MAY. Fragment-free input and empty Accept avoid using the two previously failing URL/option behaviors as premises or silently repairing them.
